# plan.md — Jigsaw Puzzle на C++ + Raylib

## Версия плана

2.0

---

## 1. Цель проекта

Разработать кроссплатформенную игру-пазл (jigsaw puzzle) на C++ с использованием библиотеки Raylib.

Игра должна работать:

- на десктопе: Windows / Linux / macOS;
- на Android: телефон и планшет.

Основной игровой процесс:

1. Игрок выбирает картинку из папки с изображениями.
2. Выбирает количество кусочков, на которые нужно разрезать картинку.
3. Кусочки можно перемещать мышью или пальцем.
4. Кусочки можно поворачивать на 90 градусов.
5. Сцену можно масштабировать:
   - zoom in;
   - zoom out;
   - reset zoom;
   - fit all, то есть показать всю область целиком.
6. Кусочки должны быть не простыми прямоугольниками, а параметризованными jigsaw-элементами.
7. Каждый кусочек должен быть уникальным.
8. Неправильные кусочки не должны подходить друг к другу и не должны соединяться.
9. Если два кусочка соединены правильно, они становятся одним неделимым блоком.
10. Блоки можно перемещать и поворачивать целиком.
11. Если два блока соединены правильно, они объединяются в один блок.
12. Полностью собранный пазл становится единым блоком, состоящим из всех кусочков.

## 5. Основные игровые сущности

### 5.1. Piece — кусочек пазла

```cpp
struct Piece
{
    int id;

    int gridX;      // правильная колонка в исходной сетке
    int gridY;      // правильная строка в исходной сетке

    Texture2D texture;

    Vector2 position;   // мировые координаты центра кусочка
    int rotation;       // 0, 1, 2, 3, означает 0°, 90°, 180°, 270°

    int blockId;        // идентификатор блока, к которому принадлежит кусочек

    PieceEdges edges;   // параметризованные края кусочка
};
```

---

### 5.2. Block — неделимый блок

```cpp
struct Block
{
    int id;

    std::vector<int> pieceIds;

    Rectangle bounds;   // ограничивающий прямоугольник блока
    Vector2 center;     // центр блока для вращения
};
```

---

### 5.3. PuzzleBoard — игровое поле

```cpp
struct PuzzleBoard
{
    Texture2D originalImage;

    int rows;
    int cols;

    float cellSize;

    std::vector<Piece> pieces;
    std::vector<Block> blocks;

    bool completed;
};
```

## 6. Состояния игры

Игра должна использовать конечный автомат состояний.

```text
LoadingState
    ↓
MenuState
    ↓
DifficultyState
    ↓
PlayState
    ↓
CompletedState
```

---

### 6.1. LoadingState

Задачи:

- инициализировать окно;
- инициализировать Raylib;
- загрузить конфигурацию;
- подготовить список изображений;
- показать заглушку загрузки.

---

### 6.2. MenuState

Задачи:

- показать список изображений из папки;
- позволить выбрать изображение;
- показать превью;
- перейти к выбору сложности.

---

### 6.3. DifficultyState

Задачи:

- показать выбранное изображение;
- позволить выбрать количество кусочков;
- начать игру.

Варианты:

```text
9 кусочков
16 кусочков
25 кусочков
36 кусочков
49 кусочков
64 кусочка
```

---

### 6.4. PlayState

Основной игровой экран.

Задачи:

- отображать кусочки;
- обрабатывать перетаскивание;
- обрабатывать поворот;
- обрабатывать масштабирование;
- проверять правильность соединений;
- проверять совместимость параметризованных краёв;
- объединять блоки;
- отслеживать завершение пазла.

---

### 6.5. CompletedState

Задачи:

- показать собранное изображение;
- показать поздравление;
- предложить:
  - собрать тот же пазл снова;
  - выбрать другое изображение;
  - выйти в меню.

### 8.3. Рекомендуемая логика touch-ввода

Чтобы избежать конфликтов жестов:

1. Если касание началось на кнопке UI — обрабатывается кнопка.
2. Если касание началось на кусочке — начинается перетаскивание блока.
3. Если касание началось на пустом фоне — начинается панорама камеры.
4. Если два пальца — включается pinch-zoom.
5. Поворот лучше делать через отдельную кнопку, а не через double tap, чтобы избежать случайных срабатываний.
6. Zoom To Selected лучше делать через отдельную кнопку или двойной тап по выбранному блоку, если это не конфликтует с другими жестами.

## 10. Камера и масштабирование сцены

### 10.1. Camera2D

Использовать `Camera2D`:

```cpp
Camera2D camera = {};
camera.target = { 0, 0 };
camera.offset = { screenWidth / 2.0f, screenHeight / 2.0f };
camera.rotation = 0.0f;
camera.zoom = 1.0f;
```

---

### 10.2. Требования к зуму

Необходимо реализовать:

```text
Zoom In
Zoom Out
Reset Zoom
Fit All
Zoom To Selected, опционально
```

---

### 10.3. Zoom In / Zoom Out

Zoom In:

```cpp
camera.zoom *= zoomFactor;
```

Zoom Out:

```cpp
camera.zoom /= zoomFactor;
```

Пример:

```cpp
const float zoomFactor = 1.15f;
const float minZoom = 0.2f;
const float maxZoom = 4.0f;

camera.zoom = Clamp(camera.zoom, minZoom, maxZoom);
```

---

### 10.4. Зум относительно курсора или pinch-центра

Чтобы приближать место, где находится курсор или центр жеста:

```cpp
Vector2 screenPoint = GetMousePosition();

Vector2 worldBefore = GetScreenToWorld2D(screenPoint, camera);

camera.zoom = Clamp(camera.zoom * factor, minZoom, maxZoom);

Vector2 worldAfter = GetScreenToWorld2D(screenPoint, camera);

camera.target.x += worldBefore.x - worldAfter.x;
camera.target.y += worldBefore.y - worldAfter.y;
```

Аналогично можно использовать середину между двумя touch-точками для pinch-zoom.

---

### 10.5. Reset Zoom

Reset Zoom должен возвращать камеру к заранее определённому виду.

Например:

```cpp
camera.zoom = defaultZoom;
camera.target = defaultTarget;
```

Рекомендуется:

- `defaultZoom = 1.0f`;
- `defaultTarget` — центр собранного пазла или центр игрового мира.

---

### 10.6. Fit All

Fit All должен показывать всю игровую область целиком.

Алгоритм:

1. Вычислить общий bounding box всех кусочков или всех блоков.
2. Добавить отступы.
3. Подобрать такой zoom, чтобы вся область помещалась на экран.
4. Установить target в центр области.

Псевдокод:

```cpp
Rectangle FitAll(Rectangle worldBounds, Vector2 screenSize, float margin)
{
    float width = worldBounds.width + margin * 2.0f;
    float height = worldBounds.height + margin * 2.0f;

    float zoomX = screenSize.x / width;
    float zoomY = screenSize.y / height;

    camera.zoom = Clamp(Min(zoomX, zoomY), minZoom, maxZoom);
    camera.target = {
        worldBounds.x + worldBounds.width * 0.5f,
        worldBounds.y + worldBounds.height * 0.5f
    };
}
```

---

### 10.7. Zoom To Selected

Оциональная функция.

Если выбран блок, можно приблизить его:

```cpp

```

Это удобно на телефонах и планшетах, чтобы быстро рассмотреть конкретную область.

## 11. Параметризованные уникальные кусочки

### 11.1. Требование

Кусочки не должны быть простыми прямоугольниками.

Каждый кусочек должен иметь параметризованную jigsaw-форму:

- выступы;
- впадины;
- уникальные изгибы;
- уникальные размеры выступов;
- уникальные пропорции;
- уникальные скругления;
- уникальные смещения контрольных точек.

Неправильные кусочки не должны подходить друг к другу.

---

### 11.2. Края кусочка

Каждый кусочек имеет 4 стороны:

```text
TOP
RIGHT
BOTTOM
LEFT
```

Типы краёв:

```text
FLAT   — ровный край, если кусочек граничит с краем изображения
TAB    — выступающая часть
BLANK  — вдавленная часть
```

---

### 11.3. EdgeProfile

Для каждой стороны хранится параметризованный профиль.

```cpp
enum class EdgeType
{
    Flat,
    Tab,
    Blank
};

struct EdgeProfile
{
    int edgeId;         // уникальный идентификатор общей границы
    int sign;           // +1 для Tab, -1 для Blank, 0 для Flat

    float tabLength;    // длина выступа
    float tabWidth;     // ширина выступа
    float neckWidth;    // ширина шейки
    float curvatureA;   // параметр кривизны
    float curvatureB;   // параметр кривизны
    float asymmetry;    // асимметрия выступа
    float jitter;       // небольшой случайный шум формы
    float cornerRadius; // скругление углов, опционально

    uint32_t seed;      // seed генерации конкретного края
    uint64_t hash;      // хэш профиля для проверки совместимости
};
```

---

### 11.4. PieceEdges

```cpp
struct PieceEdges
{
    EdgeProfile top;
    EdgeProfile right;
    EdgeProfile bottom;
    EdgeProfile left;
};
```

---

### 11.5. Уникальность кусочков

Каждый внутренний край между двумя соседними кусочками генерируется один раз.

Например, граница между:

```text
Piece A справа
Piece B слева
```

имеет один и тот же `edgeId`, но противоположные `sign`.

Для кусочка A:

```text
right.edgeId = 101
right.sign = +1
right.tabLength = 0.32
right.tabWidth = 0.41
...
```

Для кусочка B:

```text
left.edgeId = 101
left.sign = -1
left.tabLength = 0.32
left.tabWidth = 0.41
...
```

То есть геометрия комплементарна.

Внешние края изображения:

```text
edgeId = -1
sign = 0
type = Flat
```

---

### 11.6. Гарантия уникальности

Для уникальности кусочков:

1. Каждая внутренняя граница получает уникальный `edgeId`.
2. Каждая внутренняя граница получает уникальный набор параметров.
3. Каждый кусочек получает комбинацию из четырёх краёв.
4. Можно вычислять `pieceHash`:

```cpp
pieceHash =
    hash(top) ^
    rotate(hash(right), 1) ^
    rotate(hash(bottom), 2) ^
    rotate(hash(left), 3);
```

5. Если требуется строгая уникальность, хранить множество `pieceHash` и перегенерировать параметры при коллизии.

На практике уникальные `edgeId` уже делают каждый кусочек уникальным в рамках сетки.

## 12. Генерация параметризованной формы кусочка

### 12.1. Общая идея

Для каждого кусочка:

1. Определить его клетку в сетке.
2. Определить типы и параметры четырёх краёв.
3. Построить контур кусочка.
4. Растеризовать контур в альфа-маску.
5. Вырезать часть изображения по маске.
6. Создать `Texture2D`.

---

### 12.2. Запас под выступы

Так как выступы могут выходить за границы клетки, текстура кусочка должна иметь поля.

Например:

```text
cellSize = 200 px
tabMargin = 50 px

textureSize = cellSize + 2 * tabMargin
```

---

### 12.3. Построение контура

Каждая сторона кусочка строится как кривая.

Для стороны:

```text
start point -> control points -> end point
```

Параметры `tabLength`, `tabWidth`, `curvatureA`, `curvatureB`, `asymmetry`, `jitter` влияют на контрольные точки Bezier-кривых.

Для `Flat`:

```text
прямая линия
```

Для `Tab`:

```text
выступ наружу
```

Для `Blank`:

```text
впадина внутрь
```

---

### 12.4. Комплементарность

Если один кусочек имеет справа `Tab`, то соседний кусочек слева должен иметь `Blank` с теми же параметрами.

То есть:

```text
A.right = Tab(profile)
B.left = Blank(profile)
```

Это гарантирует, что правильные соседи визуально и логически подходят друг к другу.

---

### 12.5. Растеризация маски

Варианты:

1. Программная растеризация полигона в `Image`.
2. Использование triangulation и рисование треугольников.
3. Использование shader-based masking, если платформа позволяет.
4. Генерация SDF-маски, опционально.

Для MVP рекомендуется:

```text
построить полигон -> заполнить его в Image -> применить как альфа-маску
```

## 13. Запрет соединения неправильных кусочков

### 13.1. Уровни защиты

Неправильные кусочки не должны соединяться.

Для этого использовать несколько уровней проверки:

1. Проверка правильных соседей по сетке.
2. Проверка совместимости `edgeId`.
3. Проверка противоположности `sign`.
4. Проверка совпадения хэша профиля.
5. Проверка одинаковой ориентации блоков.
6. Проверка расстояния для snap.

---

### 13.2. Правильные соседи

Два кусочка могут быть соединены, только если они являются соседями в исходной сетке:

```cpp
abs(a.gridX - b.gridX) + abs(a.gridY - b.gridY) == 1
```

Если кусочки не являются соседями, они не соединяются никогда.

---

### 13.3. Совместимость краёв

Если `B` находится справа от `A`:

```text
A.right должен подходить к B.left
```

Если `B` находится снизу от `A`:

```text
A.bottom должен подходить к B.top
```

Если `B` находится слева от `A`:

```text
A.left должен подходить к B.right
```

Если `B` находится сверху от `A`:

```text
A.top должен подходить к B.bottom
```

---

### 13.4. Функция совместимости

```cpp
bool AreEdgesCompatible(const EdgeProfile& a, const EdgeProfile& b)
{
    if (a.edgeId != b.edgeId)
        return false;

    if (a.sign != -b.sign)
        return false;

    if (a.hash != b.hash)
        return false;

    return true;
}
```

Для плоских краёв:

```cpp
if (a.sign == 0 && b.sign == 0 && a.edgeId == -1)
    return true;
```

Но плоские края не используются для соединения двух кусочков, только для границы изображения.

---

### 13.5. Визуальная несовместимость

Так как форма генерируется из параметров, неправильные края будут визуально отличаться:

- разная длина выступа;
- разная ширина;
- разная кривизна;
- разная асимметрия;
- разный jitter;
- разный hash профиля.

Даже если два края случайно выглядят похоже, логика соединения всё равно проверяет `edgeId` и `hash`, поэтому они не соединятся.

---

### 13.6. Опциональная физическая защита

Можно дополнительно запретить визуальное «плотное прилегание» неправильных кусочков.

Варианты:

1. Не примагничивать несовместимые края.
2. Показывать красную подсветку при попытке соединить неправильные кусочки.
3. Использовать polygon collision detection, чтобы несовместимые формы не входили друг в друга слишком плотно.

Для первой версии рекомендуется:

```text
не соединять неправильные кусочки и не показывать snap-подсказку для них
```

Polygon collision можно добавить позже как улучшение.

## 16. Поворот кусочков и блоков

### 16.1. Дискретный поворот

Поворот только на 90 градусов.

```cpp
rotation = 0; // 0°
rotation = 1; // 90°
rotation = 2; // 180°
rotation = 3; // 270°
```

Новое значение:

```cpp
rotation = (rotation + 1) % 4;
```

---

### 16.2. Поворот блока

Блок вращается целиком вокруг своего центра.

Алгоритм:

1. Вычислить центр блока.
2. Для каждого кусочка:
   - повернуть его позицию вокруг центра на 90°;
   - увеличить его `rotation` на 1.
3. Обновить границы блока.

---

### 16.3. Формула поворота вектора на 90°

Для поворота против часовой стрелки:

```cpp
Vector2 Rotate90CounterClockwise(Vector2 v)
{
    return { -v.y, v.x };
}
```

Для поворота по часовой стрелке:

```cpp
Vector2 Rotate90Clockwise(Vector2 v)
{
    return { v.y, -v.x };
}
```

Для произвольного количества поворотов:

```cpp
Vector2 Rotate90(Vector2 v, int times)
{
    times = ((times % 4) + 4) % 4;

    for (int i = 0; i < times; ++i)
    {
        v = { -v.y, v.x };
    }

    return v;
}
```

## 17. Правильное соединение кусочков

### 17.1. Основная идея

Каждый кусочек знает своё правильное место в сетке:

```cpp
gridX
gridY
```

Два кусочка считаются соседями, если:

```cpp
abs(a.gridX - b.gridX) + abs(a.gridY - b.gridY) == 1
```

---

### 17.2. Ожидаемое смещение соседей

Если кусочек `B` должен находиться справа от кусочка `A`:

```text
solvedDelta = { cellSize, 0 }
```

Если снизу:

```text
solvedDelta = { 0, cellSize }
```

Если слева:

```text
solvedDelta = { -cellSize, 0 }
```

Если сверху:

```text
solvedDelta = { 0, -cellSize }
```

Но текущий блок может быть повёрнут.

Поэтому смещение нужно поворачивать на текущий угол блока.

---

### 17.3. Ожидаемая позиция соседа

```cpp
Vector2 solvedDelta =
{
    (b.gridX - a.gridX) * cellSize,
    (b.gridY - a.gridY) * cellSize
};

Vector2 rotatedDelta = Rotate90(solvedDelta, a.rotation);

Vector2 expectedBPosition = a.position + rotatedDelta;
```

---

### 17.4. Условие соединения

Кусочки можно соединить, если:

1. Они находятся в разных блоках.
2. Они являются правильными соседями.
3. Их параметризованные края совместимы.
4. Их ориентация совместима.
5. Расстояние между текущей и ожидаемой позицией меньше порога.

---

### 17.5. Совместимость ориентации

Для упрощённой логики:

```cpp
if (a.rotation != b.rotation)
{
    // не соединять
}
```

Это означает, что правильно соединённые кусочки всегда имеют одинаковый текущий поворот.

Например:

```text
0° и 0°   — можно
90° и 90° — можно
180° и 180° — можно
270° и 270° — можно
```

Но:

```text
0° и 90° — нельзя
```

---

### 17.6. Порог примагничивания

Рекомендуемый порог:

```text
snapThreshold = cellSize * 0.12
```

или

```text
snapThreshold = cellSize * 0.18
```

Для фигурных кусочков можно использовать чуть меньший порог, чем для прямоугольных, чтобы соединение ощущалось более точным.

---

## 18. Snap-система

### 18.1. Когда проверять

Проверку соединений нужно запускать:

- после окончания перетаскивания блока;
- после поворота блока;
- опционально, во время перетаскивания для подсветки возможного соединения.

---

### 18.2. Оптимизация проверки

Не нужно проверять все кусочки со всеми.

После перемещения блока `G`:

1. Для каждого кусочка из блока `G`.
2. Проверять только его правильных соседей.
3. Если сосед находится в другом блоке — проверить snap.
4. Если найдено соединение — объединить блоки.
5. После объединения повторить проверку, потому что новый блок может присоединиться к третьему блоку.

---

### 18.3. Псевдокод snap-системы

```cpp
bool TrySnapBlock(int movedBlockId)
{
    for each pieceA in movedBlock
    {
        for each neighborPieceB of pieceA
        {
            if pieceA.blockId == neighborPieceB.blockId
                continue;

            if pieceA.rotation != neighborPieceB.rotation
                continue;

            if !AreNeighborEdgesCompatible(pieceA, neighborPieceB)
                continue;

            Vector2 expected = ExpectedPosition(pieceA, neighborPieceB);

            if Distance(neighborPieceB.position, expected) < snapThreshold
            {
                AlignBlock(neighborPieceB.blockId, expected - neighborPieceB.position);
                MergeBlocks(pieceA.blockId, neighborPieceB.blockId);
                return true;
            }
        }
    }

    return false;
}
```

---

### 18.4. Проверка совместимости соседей

```cpp
bool AreNeighborEdgesCompatible(const Piece& a, const Piece& b)
{
    int dx = b.gridX - a.gridX;
    int dy = b.gridY - a.gridY;

    if (dx == 1 && dy == 0)
    {
        return AreEdgesCompatible(a.edges.right, b.edges.left);
    }

    if (dx == -1 && dy == 0)
    {
        return AreEdgesCompatible(a.edges.left, b.edges.right);
    }

    if (dx == 0 && dy == 1)
    {
        return AreEdgesCompatible(a.edges.bottom, b.edges.top);
    }

    if (dx == 0 && dy == -1)
    {
        return AreEdgesCompatible(a.edges.top, b.edges.bottom);
    }

    return false;
}
```

## 19. Объединение блоков

### 19.1. Union-Find или ручное объединение

Для MVP можно использовать простой подход:

1. Найти два блока, которые нужно объединить.
2. Выбрать больший блок как основной.
3. Перенести `pieceIds` из меньшего блока в больший.
4. Обновить у всех кусочков `blockId`.
5. Удалить меньший блок.
6. Пересчитать границы и центр большего блока.

---

### 19.2. Алгоритм объединения

```text
MergeBlocks(blockA, blockB)
{
    if blockB.pieceIds.size() > blockA.pieceIds.size()
        swap(blockA, blockB)

    for pieceId in blockB.pieceIds
    {
        pieces[pieceId].blockId = blockA.id;
        blockA.pieceIds.push_back(pieceId);
    }

    remove blockB;

    RecalculateBounds(blockA);
}
```

---

### 19.3. Пересчёт границ блока

Нужно вычислить:

```cpp
Rectangle bounds;
Vector2 center;
```

На основе позиций и размеров всех кусочков блока.

Для фигурных кусочков нужно учитывать не только `cellSize`, но и поля текстур, то есть реальные визуальные границы кусочков.

## 20. Завершение пазла

### 20.1. Условие победы

Пазл собран, если:

```text
Количество блоков == 1
```

и этот блок содержит все кусочки.

```cpp
if (blocks.size() == 1 && blocks[0].pieceIds.size() == totalPieces)
{
    completed = true;
}
```

---

### 20.2. Ориентация финального блока

Возможны два варианта:

### Вариант A: считать собранным в любом повороте

Если все кусочки соединены правильно, но весь блок повёрнут на 90°, 180° или 270°, пазл всё равно считается собранным.

Плюсы:

- проще;
- дружелюбнее к игроку.

---

### Вариант B: требовать ориентацию 0°

Пазл считается полностью собранным, если:

```text
blocks.size() == 1
blocks[0].rotation == 0
```

Плюсы:

- итоговая картинка всегда расположена правильно.

---

### Рекомендуемый вариант

Считать пазл собранным, если он является единым блоком.

После этого можно:

1. Показать экран победы.
2. Автоматически плавно повернуть блок к 0°.
3. Отцентрировать камеру.
4. Выполнить Fit All.

## 27. Возможные риски

### 27.1. Сложность сборки под Android

Риск:

```text
Android NDK, Gradle и Raylib могут быть сложны в настройке.
```

Решение:

- использовать официальный Android-шаблон Raylib;
- сначала собрать простой пример;
- только потом добавлять игру.

---

### 27.2. Конфликты жестов

Риск:

```text
Перетаскивание кусочка можно перепутать с панорамой камеры.
```

Решение:

- чётко определять, началось касание на кусочке или на фоне;
- поворот делать через кнопку;
- pinch-zoom включать только при двух пальцах.

---

### 27.3. Доступ к файлам на Android

Риск:

```text
LoadDirectoryFiles может плохо работать с assets внутри APK.
```

Решение:

- копировать изображения из assets во внутреннее хранилище;
- использовать список изображений из манифеста, если нужно.

---

### 27.4. Производительность

Риск:

```text
Много отдельных текстур и фигурные маски могут тормозить на слабых устройствах.
```

Решение:

- ограничить максимальный размер изображения;
- использовать не более 64–100 кусочков;
- кэшировать маски и полигоны;
- при необходимости собрать атлас текстур.

---

### 27.5. Генерация фигурных кусочков

Риск:

```text
Построение качественных jigsaw-кривых и масок может быть сложным.
```

Решение:

- начать с простых параметризованных выступов;
- использовать Bezier-кривые;
- постепенно улучшать форму;
- добавить визуальные пресеты профилей.

---

### 27.6. Визуальная похожесть неправильных краёв

Риск:

```text
Два неправильных края могут случайно выглядеть похоже.
```

Решение:

- соединение проверяется не только формой, но и `edgeId`, `sign`, `hash`;
- можно увеличить диапазон уникальных параметров;
- можно добавить явную подсветку неправильного соединения.
