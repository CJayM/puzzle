# Виртуальные пиксели (dp) в UI

Механизм, обеспечивающий **одинаковый физический размер кнопок и надписей** на
любом устройстве (телефон, планшет, PC) независимо от разрешения экрана и
плотности пикселей.

## Идея

UI размечается в **логических единицах (dp)**. Один логический пиксель
превращается в разное число физических пикселей в зависимости от плотности
экрана устройства:

```
физический размер = логический размер × UiScale
```

где:

```
UiScale = dpiScale × UserScale
```

- `dpiScale` — плотность устройства (Android: `density = dpi / 160`);
- `UserScale` — пользовательская настройка «Размер интерфейса»:
  - «Маленький» — 0.8
  - «Нормальный» — 1.0
  - «Большой» — 1.25

Например, кнопка 70 dp на телефоне с плотностью 440 dpi (`dpiScale = 2.75`)
займёт 192 физических пикселя, а на планшете 320 dpi (`dpiScale = 2.0`) —
140 физических пикселей. В миллиметрах/дюймах размер одинаковый.

## Где задаётся

| Параметр | Место |
|---|---|
| `dpiScale` | `Config::Instance().dpiScale` (по умолчанию 1.0) |
| Установка на Android | `Game::Init` — `AConfiguration_getDensity(app->config) / 160.0f` |
| Установка на PC | не выполняется — остаётся 1.0 (монитор 96 dpi) |
| `UserScale` | `SettingsState::UserScale()` из `SettingsData::uiScale` (сохраняется в `settings.dat`) |

## Расчёт размера и положения

В каждом состоянии UI определён набор статических функций:

```cpp
// коэффициент: логические → физические пиксели
static float UiScale() { return Config::Instance().dpiScale * SettingsState::UserScale(); }

// логический (виртуальный) размер окна
static float LogW() { return GetScreenWidth() / UiScale(); }
static float LogH() { return GetScreenHeight() / UiScale(); }
```

Все координаты и размеры в коде — **логические** (например, кнопка
`btnRect(10, 8, 50, 34)` — это 50×34 dp). Вспомогательный `btnRect`
масштабирует их:

```cpp
static Rectangle btnRect(float x, float y, float w, float h)
{
    float s = UiScale();
    return Rectangle{ x * s, y * s, w * s, h * s };
}
```

### Примеры (dp)

| Элемент | Логический размер |
|---|---|
| Кнопки HUD (игровой экран) | 70×34, отступ от верха 8 |
| Кнопки главного меню | 280×56, интервал 12 |
| Кнопки настроек | 260×44 |
| Плитка картинки | 96×96, зазор 6 |
| Превью картинки | до `min(LogW·7/16, LogH−190)` |
| Кнопки «Да/Нет» (диалог) | 120×44 |
| Кнопка «Начать» на превью | 200×46 |

### Привязка к краям экрана

Элементы у краёв считаются от логической ширины окна, а не от фиксированной
координаты:

```cpp
// кнопка «Глаз» — правый край на LogW − 8 (отступ 8 dp)
btnRect(LogW() - 78.0f, 8.0f, 70.0f, 34.0f)
// кнопка «Меню» — слева от неё
btnRect(LogW() - 155.0f, 8.0f, 70.0f, 34.0f)
```

Это гарантирует, что кнопки всегда видны целиком при любом масштабе
и на любой ширине экрана.

## Логический размер окна на разных устройствах

`LogW × LogH` — «виртуальный экран» в dp, на котором строится раскладка:

| Устройство | Физический экран | density | Логический экран (dp) |
|---|---|---|---|
| Телефон (портрет) | 1080 × 2400 | 2.75 | ≈ 393 × 873 |
| Телефон (ландшафт) | 2400 × 1080 | 2.75 | ≈ 873 × 393 |
| Планшет (ландшафт) | 2560 × 1600 | 2.0 | 1280 × 800 |
| ПК / окно 1280×720 | 1280 × 720 | 1.0 | 1280 × 720 |

На PC `UiScale = UserScale` (dpiScale = 1.0), поэтому 1 логический пиксель =
1 физический — привычное поведение без изменений.

## Адаптивность раскладки

Поскольку логическая ширина разная (393 dp на телефоне против 1280 dp на
планшете), часть раскладки **пересчитывается от `LogW`**:

- **Список категорий/подкатегорий**: `ListW() = min(400, LogW − 32)` — на
  узком экране список занимает всю ширину.
- **Сетка плиток**: размер плитки фиксирован (96 dp), а **число колонок
  адаптивное**:

  ```cpp
  TileCols() = max(3, (int)(LogW * 0.58 / (96 + 6)))
  ```

  Телефон (~393 dp) → 3 колонки; планшет (~1280 dp) → 7–8 колонок.
- **Превью**: центр правой половины `LogW·3/4`, максимальный размер
  `min(LogW·7/16, LogH − 190)`.
- **Диалоги и заголовки** центрируются по физическому центру окна
  (`sw/2`, `sh/2`), кнопки внутри — в dp.

## Портретная и альбомная ориентации

Игра поддерживает **обе ориентации**:

1. **Android**: в манифесте нет `screenOrientation` — при повороте Android
   пересоздаёт Activity; игра стартует с новым физическим размером окна,
   `dpiScale` и `LogW/LogH` пересчитываются автоматически (см.
   `android/app/src/main/AndroidManifest.xml`).
2. **Раскладка перестраивается**: при портрете логическая ширина меньше →
   колонок плиток меньше, список уже, кнопки HUD занимают ту же ширину в dp
   (они прижаты к краям, поэтому всегда умещаются).
3. **Прогресс партии** при повороте не теряется: `PlayState` автосохраняет
   игру каждые 5 секунд; после пересоздания Activity «Продолжить» возвращает
   на то же место.

## Ограничения и примечания

- `dpiScale` берётся из `AConfiguration_getDensity` — на некоторых устройствах
  система может вернуть номинальную плотность, слегка отличающуюся от
  реальной; при необходимости формулу можно уточнить.
- На PC `dpiScale = 1.0` даже при масштабировании Windows (125%/150%) — окно
  игры обычно запускается в фиксированном размере; если понадобится учёт
  системного масштаба, можно использовать `GetMonitorScale()` из raylib.
- Шрифт рендерится как **SDF** (см. `Game::Init`, shader `sdf.fs`), поэтому
  масштабирование текста от 11 до 50 dp остаётся резким при любом размере.
